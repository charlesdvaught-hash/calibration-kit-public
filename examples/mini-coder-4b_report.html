The rule

Implementable as written. Every number below was measured on this model, on this run.

  1. Do not gate generation on entropy. No entropy statistic separates this model's correct from incorrect output well enough to act on, so an entropy gate costs compute and buys nothing.
  2. On a failed generation, repair in this order: test_retry. This ordering is greedy set cover over what actually recovered failures in this run, not a preference — test_retry alone recovered 4 of 11.
  3. When the failure is a logic error, route to test_retry first (3/4, 75%), ahead of skeleton_fill 25%, temp_retry 0%.
  4. When the failure is an assertion error, expect little. The best strategy tested, test_retry, recovered only 1 of 7 (14%). Try it once, then escalate rather than working through the rest.
  5. Stop after the ordered chain. 4 of 11 failures were recoverable by any strategy tested; the remaining 7 were not recovered by any of them, so further retries on those are spend without evidence behind it.

Does entropy predict correctness here?

CorrectIncorrect

Correct generations averaged max_entropy 1.558; incorrect ones 1.518. The distributions overlap almost completely — that overlap, not the gap between the means, is the finding.

A permutation test puts that difference at p=0.8069, against an alpha of 0.05. Reshuffling which generations were labelled correct reproduces a gap this large routinely.

Across 10 candidate statistics the largest effect was mean_entropy at d=+0.377 (high=good), and it does not survive correction for the number tested.

4 of 11 failures were recoverable by at least one repair strategy. Recovery is measured directly — break it, repair it, re-run the tests — so these counts do not depend on any of the statistical argument above.

Power: underpowered. This run could only reliably detect an effect of d>=1.01; the effect it saw was d=+0.09. That means this run cannot tell 'no entropy signal' apart from 'too few failures to see one'. Confirming an effect this small would take --repeats 249, which is not a practical run. Treat entropy as unusable for this model: even if the effect is real, it is too small to route decisions on.
