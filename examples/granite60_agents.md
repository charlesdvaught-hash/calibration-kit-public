# Calibration Playbook -- granite

Calibrated on 2026-09-05 12:24. 60 probe runs, 8 failures, 24 intervention runs.

This playbook was generated by running the model on calibration tasks and measuring what actually worked. Every rule below includes the data behind it. Rules that didn't hold for this model are listed under "What we tested that didn't work" -- don't apply them.

> **This is a single-run snapshot.** It reports what one calibration found with one task set, one architect, and one set of config knobs. Do NOT compare playbooks across runs and conclude a model 'got better' -- differences between runs may come from changed tasks, configs, or methodology, not from the model itself. Each playbook stands alone.

> **Scope boundary.** The pipeline can sweep large candidate spaces -- it may generate many candidates to find the one that fixes an obscure Python bug. What calibration changes is *how efficiently* it searches that space. Where a calibrated signal exists it lets you order candidates and bail early; on every model calibrated so far, no entropy signal has survived significance testing, so assume the full sweep unless the entropy section below says otherwise. What calibration reliably buys is the repair order and the per-error-type routing: which strategy to reach for, and when to stop. It does not give the model context it doesn't have -- if the model can't see the bug, no amount of sweeping will produce the right answer.

## The rule

Apply these directly. Every number comes from this model's own calibration run; the sections below are the evidence behind them.

1. **Do not gate generation on entropy.** No entropy statistic separates this model's correct from incorrect output well enough to act on. An entropy gate here spends compute and buys nothing.
2. **On failure, repair in this order:** `skeleton_fill -> test_retry`. Learned by greedy set cover over what actually recovered failures in this run -- `skeleton_fill` alone recovered 3 of 8.
3. **On a logic error, route to `test_retry` first** (1/4, 25%), ahead of `skeleton_fill` 25%, `temp_retry` 0%.
4. **On an assertion error, route to `test_retry` first** (2/3, 67%), ahead of `skeleton_fill` 67%, `temp_retry` 0%.
5. **On a syntax error, stop.** Nothing recovered it -- all 3 strategies scored 0/1. Escalate or drop the task rather than spending retries.
6. **Stop after the chain.** 4 of 8 failures were recoverable by any strategy tested; the other 4 were recovered by none of them. Further retries on those are spend with no evidence behind it.
