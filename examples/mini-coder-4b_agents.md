# Calibration Playbook -- mini-coder-4b-q8-0

Calibrated on 2026-09-04 13:35. 36 probe runs, 11 failures, 44 intervention runs.

This playbook was generated by running the model on calibration tasks and measuring what actually worked. Every rule below includes the data behind it. Rules that didn't hold for this model are listed under "What we tested that didn't work" -- don't apply them.

> **This is a single-run snapshot.** It reports what one calibration found with one task set, one architect, and one set of config knobs. Do NOT compare playbooks across runs and conclude a model 'got better' -- differences between runs may come from changed tasks, configs, or methodology, not from the model itself. Each playbook stands alone.

> **Scope boundary.** The pipeline can sweep large candidate spaces -- it may generate 200 candidates to find the one that fixes an obscure Python bug. What calibration changes is *how efficiently* it searches that space. A calibrated entropy signal lets you test the most-likely-wrong candidates first and bail early on hopeless runs, cutting a 200-candidate sweep to ~60. Without a signal (or if the signal doesn't work for this model), you test all 200. The playbook does not give the model context it doesn't have -- if the model can't see the bug, no amount of sweeping will produce the right answer. But if the answer is in the candidate space, calibration finds it with less wasted compute.

1. **Do not gate generation on entropy.** No entropy statistic separates this model's correct from incorrect output well enough to act on. An entropy gate here spends compute and buys nothing.
2. **On failure, repair in this order:** `test_retry`. Learned by greedy set cover over what actually recovered failures in this run -- `test_retry` alone recovered 4 of 11.
3. **On a logic error, route to `test_retry` first** (3/4, 75%), ahead of `skeleton_fill` 25%, `temp_retry` 0%.
4. **On an assertion error, expect little.** The best strategy tested, `test_retry`, recovered 1/7 (14%). Try it once, then escalate.
5. **Stop after the chain.** 4 of 11 failures were recoverable by any strategy tested; the other 7 were recovered by none of them. Further retries on those are spend with no evidence behind it.
