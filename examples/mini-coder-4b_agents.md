> **This is a single-run snapshot.** It reports what one calibration found with one task set, one architect, and one set of config knobs. Do NOT compare playbooks across runs and conclude a model 'got better' -- differences between runs may come from changed tasks, configs, or methodology, not from the model itself. Each playbook stands alone.

> **Scope boundary.** The pipeline can sweep large candidate spaces -- it may generate 200 candidates to find the one that fixes an obscure Python bug. What calibration changes is *how efficiently* it searches that space. A calibrated entropy signal lets you test the most-likely-wrong candidates first and bail early on hopeless runs, cutting a 200-candidate sweep to ~60. Without a signal (or if the signal doesn't work for this model), you test all 200. The playbook does not give the model context it doesn't have -- if the model can't see the bug, no amount of sweeping will produce the right answer. But if the answer is in the candidate space, calibration finds it with less wasted compute.
