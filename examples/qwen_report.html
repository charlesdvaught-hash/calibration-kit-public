The rule

Implementable as written. Every number below was measured on this model, on this run.

  1. Do not gate generation on entropy. No entropy statistic separates this model's correct from incorrect output well enough to act on, so an entropy gate costs compute and buys nothing.
  2. On a failed generation, repair in this order: test_retry → temp_retry → skeleton_fill → decompose. This ordering is greedy set cover over what actually recovered failures in this run, not a preference — test_retry alone recovered 18 of 33.
  3. When the failure is a logic error, route to test_retry first (18/20, 90%), ahead of arch_trace_long 50%, arch_trace_short 40%.
  4. When the failure is an assertion error, route to temp_retry first (6/13, 46%), ahead of skeleton_fill 23%, arch_design 23%. Do not reach for test_retry here — it is the strongest strategy on logic errors (90%) and recovered 0/13 of these.
  5. Stop after the ordered chain. 30 of 33 failures were recoverable by any strategy tested; the remaining 3 were not recovered by any of them, so further retries on those are spend without evidence behind it.

Correct generations averaged max_entropy 1.104; incorrect ones 1.037. The distributions overlap almost completely — that overlap, not the gap between the means, is the finding.

A permutation test puts that difference at p=0.3868, against an alpha of 0.05. Reshuffling which generations were labelled correct reproduces a gap this large routinely.

30 of 33 failures were recoverable by at least one repair strategy. Recovery is measured directly — break it, repair it, re-run the tests — so these counts do not depend on any of the statistical argument above.

Power: underpowered. This run could only reliably detect an effect of d>=0.54; the effect it saw was d=+0.17. That means this run cannot tell 'no entropy signal' apart from 'too few failures to see one'. Confirming an effect this small would take --repeats 102, which is not a practical run. Treat entropy as unusable for this model: even if the effect is real, it is too small to route decisions on.
